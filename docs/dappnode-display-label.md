# Dappnode display label (#1)

**The requested custom-packages row/detail label cannot be changed from this package alone on inspected Dappmanager v0.2.129.** [`PackagesList.tsx`](https://github.com/dappnode/DNP_DAPPMANAGER/blob/v0.2.129/packages/admin-ui/src/pages/packages/components/PackagesList.tsx) renders `prettyDnpName(dnp.dnpName)` in My custom packages; [`ById.tsx`](https://github.com/dappnode/DNP_DAPPMANAGER/blob/v0.2.129/packages/admin-ui/src/pages/packages/pages/ById.tsx) uses the same formatter for the installed package heading. [`format.ts`](https://github.com/dappnode/DNP_DAPPMANAGER/blob/v0.2.129/packages/admin-ui/src/utils/format.ts) derives `Uvm Tunnel` from the first label of `uvm-tunnel.public.dappnode.eth`. The [manifest type](https://github.com/dappnode/DNP_DAPPMANAGER/blob/v0.2.129/packages/types/src/manifest.ts) has descriptive metadata but no separate installed display-name property consumed by these components.

Source metadata now describes the package as **Urbit Ship Tunnel** via `shortDescription` and `description`; these **do not** change the custom-packages row or detail heading. The new `gettingStarted` Markdown explains the separate connector, its ship-only route and prerequisites; Dappmanager's Info tab can display it as a dismissible **Getting started** section (or **show** control after dismissal). Source/schema checks do not prove installed UI delivery; that requires a separately approved update and appliance readback.

The manifest `name`, Compose image/service and `TUNNEL_TOKEN` configuration are unchanged. Renaming the manifest identity is prohibited; it would not be a display-only fix. A separately authorized Dappmanager UI enhancement could use an optional trusted installed manifest display label with an identity fallback in both components, with a UI test and appliance readback. No target update, token access or core modification is performed here.
